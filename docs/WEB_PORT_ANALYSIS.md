# K45movies website port analysis

Mobile baseline `17be4e5` from `origin/main`. Provider repository inspected at `fce60ad`. The mobile app uses Expo SDK 57 and React Native 0.86. The website will live in `/web` with its own package and build. This phase records source behavior and design decisions for approval. Playback compatibility and performance require a running web build and representative streams. [Expo SDK 57 reference](https://docs.expo.dev/versions/v57.0.0/)

## Screens, navigation and Back

`App.tsx` mounts the navigation tree, provider WebView bridge and persistent classic player overlay. The native stack starts at `Tabs`. Classic tabs start at Home and return there on Android Back from another tab. YouTube uses the same initial-tab Back policy with its own tabs. For the web, use browser history for normal navigation, return focus to the opener when a dialog closes, and provide Home or the appropriate parent as an explicit fallback when a deep link has no in-site history. Closing transient panels should preserve the underlying route, scroll position and selected tab.

## Data flow by layout

**Provider Based.** Provider defaults to `vega`. Browse only the active provider. Preserve catalog ordering, filter IDs, pagination, installed-provider switching, parallel search across installed providers with partial results, provider identity on each card, and source order and labels where the app preserves them. Details consume provider `linkList`. Movie direct links and static series episode arrays resolve via `getStream`. Dynamic seasons resolve via `getEpisodes` first. Preserve episode matching across qualities and the separate selection of source server versus in-stream quality. Keep direct resume and old-entry fallback to details.

**Movie Based.** TMDB data supplies browse/search/watchlist/details, including season numbers and episode metadata. Home, Search and Watchlist can render independently of provider readiness. Detail uses `titleBridge` and `useTitleSources` to search installed providers by normalized title and title variants, then scores candidates for name, year and movie/series type and checks provider metadata. Matching uses a three-provider pool and reports pending, failed and matching states independently. Movies use applicable link groups. Series map TMDB season/episode to provider season and episode names, including dynamic load and alternate encodes. Preferred audio is an ISO language code or `none`. Infer languages from source labels, then enrich a bounded set with stream/audio metadata when needed. Ranking favors known matches while leaving other sources selectable. Show a notice when a selected source lacks the preferred track. Providers & Qualities stays available in the player, with active, failed and unchecked source state. Source switches preserve position. Episode switches update the target and can rebuild the queue.

**YouTube.** Dedicated bundled `youtube` provider with Home, Shorts, Watchlist and Settings. Topics and video/Shorts filters live in `YouTube/api.ts`. Query hooks provide pagination, de-duplication, Shorts-only filtering and prefetch for opening a video. Data includes channel, views, duration, thumbnail, aspect and live state. Local hidden/channel and subscription stores do not represent a YouTube login. Likes/dislikes are screen state. Watch route prioritizes fast playable streams, fetches detailed formats separately, filters out playback candidates without required tracks, and falls back on error. Shorts reuse player behavior and activate one clip at a time. Carry over comments, continuation/reply pagination, local watchlist, and toast feedback.

## Network and provider contracts

| Caller | Calls and data |
| --- | --- |
| `ProviderManager` | `GET /manifest.json` against the raw GitHub provider repo, accepts an array or `providers`, normalizes names and excludes the aggregate helper. Five-minute TTL and shared in-flight request. Resolves `bundleUrl` or `GET /bundled/{id}.js` for remote installs. Reconciles persisted installed IDs with the static registry and files on startup. |
| `providerApi` and native provider context | `catalog.catalog`, `posts.getPosts(filter,page)`, `posts.getSearchPosts(searchQuery,page)`, `meta.getMeta(link)`, `episodes.getEpisodes(url)`, `stream.getStream(link,type)`. These are module calls, not REST endpoints. The local registry executes bundled methods in the app JS runtime with Axios, Cheerio, helpers and KV. The remote bundle evaluates in a WebView with RPC, bridged request methods, deadlines/cancellation and cookie handling. |
| YouTube `api.ts` and hooks | Same provider posts and metadata/streams, plus `posts.getSuggestions`, `meta.getComments` with continuation for pages and replies, and fast/detail stream queries. Thumbnails can fall back to `i.ytimg.com`. |
| TMDB `tmdbApi.ts` | GET `/trending/all/week`, `/{movie|tv}/popular`, `/{movie|tv}/top_rated`, `/movie/now_playing`, `/tv/on_the_air`, `/discover/{movie|tv}` (random-page discovery, popularity sort, vote thresholds and original-language filters), `/search/multi`, `/{movie|tv}/{id}` (credits, videos, similar and movie release dates or TV content ratings), `/tv/{id}/season/{number}`. Images at `image.tmdb.org/t/p`, trailer opens YouTube. `EXPO_PUBLIC_TMDB_KEY` accepts query API key or Bearer token. |
| Stream helpers, player and subtitle service | Probe resolved candidates with HEAD and bounded ranged GET as appropriate. Playback fetches source/manifests, segments, keys/maps and subtitle assets as applicable. Audio-language enrichment can inspect HLS playlist or source metadata. Subtitle preparation fetches external tracks, parses/normalizes cues and combines with embedded tracks. |
| Other outward requests | Provider artwork and title images come from manifest/provider payloads. Preset avatar images use DiceBear. Provider modules perform their own upstream calls and can depend on cookies, context crypto, external metadata or provider-specific resolvers. Treat each provider as an adapter and verify compatibility before enabling it. |
| `K45movies-api/dev-server.js` | Local development routes are GET `/manifest.json`, `/dist/:provider/:file` and static `/dist`, `/status`, `/providers`, `/health`, plus POST `/build`. Production mobile uses published artifacts. The development build route must stay outside the public website API. |

Use the existing provider repository as the catalog/bundle source of truth. Introduce typed Next.js Route Handlers under `/api/proxy` for provider operations, metadata and playback gateway requests. Keep provider execution server-side using reviewed, pinned bundles in a restricted worker/process. Pin module/method per route and validate IDs, argument shapes, approved hostnames and redirects. Use per-provider/session cookie jars, bounded concurrency/deadlines, distributed rate limiting and streamed byte-range responses with origin cache semantics. Issue expiring playback handles for approved sources and rewrite nested HLS URI references through the same policy where media CORS or required headers prevent direct playback. Keep upstream credentials, private addresses, signed links and provider errors out of browser-visible logs and persistent state. Cache independently by data freshness and credential scope. TanStack Query handles cancellation, pagination, retry and client invalidation, with the mobile default of five-minute freshness for ordinary catalog/metadata as a starting point.

Use a server-only provider base URL. Document `NEXT_PUBLIC_TMDB_KEY` for a deliberately public API key if configured. Prefer server-only `TMDB_API_KEY` for credentials that must stay private, accessed through the same-origin metadata handler. Use a secure, HTTP-only session cookie if the approved account service offers an appropriate session contract. [Next.js Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers)

## Player behavior and browser design

| Area | Existing behavior and proposed web equivalent |
| --- | --- |
| Session | Pending state while resolving, buffer spinner and playback errors with retry. Classic overlay lives across routes and supports a draggable/resizable mini-player with controls, expand and dismiss. YouTube mini-player reopens at its captured position. Use a persistent route-shell player and lazy-load playback code. |
| Playback and seek | Play/pause, replay on end, seek bar with buffered progress, elapsed and remaining/total. Classic shows a cumulative ±10 s double-tap indicator and supports horizontal drag seeking, with vertical side gestures for brightness and volume. Adapt with pointer/touch support, keyboard controls and in-player volume. Seek preview uses time and available storyboard thumbnails, without delaying seek. |
| Speed and scale | Classic 0.25× through 2×, Fit/Cover/Stretch/100%, pinch zoom and pan/reset. Use playbackRate, object-fit and composited transforms. YouTube has pinch zoom and fullscreen. Theater widens the web player within the page. |
| Lock and controls | Auto-hide after preference delay. Lock suppresses gestures and most controls, with an explicit unlock target. Keep focusable controls and escape paths. Space, arrows, F, M, C and J/L are web shortcuts scoped away from text inputs and modal interactions. |
| Source and quality | Normalize links, headers, resolution and format. Preserve Auto/manual ABR levels separately from server, release quality, provider and audio selection. Retry recoverable transport/decoder errors, then another eligible source. Classic Android may swap TextureView/SurfaceView or hardware/software decoder. Web falls back via capability checks, hls.js recovery and another playable source. |
| Audio | Classic audio-track picker, preferred audio selection and per-source fallback. Use hls.js alternate tracks when available and feature-detect native media track access. Unsupported MP4 track combinations need a compatible alternate or upstream packaging. |
| Subtitles | Classic Off, automatic and explicit embedded/external tracks, language preference and style panel with preview, size/font/weight/color/background/opacity/shadow/placement/alignment and reset. YouTube settings list captions with Off and provide a caption toggle. Compose timed cue overlay for style and the requested adjustable subtitle delay, normalize SRT/VTT where needed, and preserve cue rendering on seek and source change. |
| Episodes | Landscape classic panel selects episodes in place, preserves the right season/quality, and closes after selection. Next Episode is explicit and switches within the same overlay. Classic onEnd stops at replay. Web episode autoplay is an added behavior that needs a default decision. YouTube onEnd advances to a related full video when its autoplay toggle is on. |
| Fullscreen and PiP | Classic orientation lock, immersive bars, PiP/background controls and screen wake behavior come from Android. Web uses Fullscreen, feature-detected PiP and supported media-session controls. In-page mini-player is the available fallback. Standard PiP presents the video element and may omit custom HTML captions or controls. |
| Resume and performance | Seek to saved position after media metadata is available. Refresh expiring source URLs from canonical IDs on resume. Use refs and a throttled time readout/progress save, preload metadata, lazy-load hls.js, bound ABR buffers and retry limits, and validate alternative sources asynchronously. Use native MP4 and native HLS where appropriate. |

Verification in Player and Polish phases should include a large ranged MP4 and a multi-rendition HLS fixture on a recorded slow bandwidth/latency profile. Report startup and seek times, stalls, dropped frames, source fallback and memory behavior with device/browser and fixture details. Tests cover quality/language ordering, stale source resume, keyboard focus, subtitle offset, error recovery and episode transitions. ## Browser limits and decisions

- The Expo plugin copies/registers `VideoDecoderModule` and `K45DohOkHttpFactory`, aligns Media3/FFmpeg dependencies, and configures native build behavior. The Kotlin decoder module reaches into native ExoPlayer. The Android Video patch has software decode, rendering fallback, retry/range/parallel data sources, HLS parser adaptations, subtitle overlay, volume gain and PiP/service handling. Browsers choose decoding, supported codec/container combinations and DNS. Prefer compatible HLS/MP4 and test alternate sources. MKV, HEVC, AV1, HDR/Dolby Vision and embedded audio/subtitles need a source/browser coverage matrix. If a provider only supplies an incompatible format, upstream packaging/transcoding would need a deployment decision.
- Browser JavaScript cannot control global brightness or volume, force OS orientation across browsers, or guarantee background playback. Use video-local brightness/volume, responsive geometry and best-effort media-session/PiP. Browser autoplay rules may require a user gesture or muted start.
- The Android provider WebView and cookie bridge are platform-specific. A same-origin server adapter addresses CORS for approved public endpoints and stream hosts. A browser iframe cannot extract third-party cross-origin cookies or page data. Where upstream requires an interactive challenge, authenticated browser state, unsupported codecs or unavailable media, report that provider capability and use an approved API/embed or playable alternate. Confirm which providers are in scope if those constraints block parity.
- Provider artifacts change independently. `scripts/build-providers.js` bundles the sibling provider repo with esbuild, generated registry and compatibility shims. For web, validate a supported provider matrix against a pinned manifest snapshot, and keep the backend publication authoritative. Existing mobile regression tests document cookie handling, static runner signatures/cancellation and SHA-1 shim behavior. Base web selection and store tests on those contracts plus browser fixtures.
- Account identity and persistence depend on the service contract described above. Decide whether web is local-profile-only initially or uses a named existing login/register/logout service. Also confirm whether classic episode autoplay, which would extend Android behavior, should default on or off.

## Phases and approval gates

1. **Analysis.** Commit this source audit to `feat/website` and review the open decisions.
2. **Scaffold and design system.** Isolated `/web` package, strict TypeScript, Next App Router, responsive shell, tokens, brand assets, accessible primitives, skeleton/toast and app navigation.
3. **Auth and data layer.** Implement the approved session contract, provider/TMDB handlers, validation/rate limits, React Query session and cache behavior, and Zustand persistence.
4. **Layouts and screens.** Provider parity, TMDB title bridge and source choice, YouTube feed/search/Shorts/watchlist, settings entry and profile and provider flows. Verify Back and deep links.
5. **Player.** Media engine, controls, source/episode switch, subtitle panel, resume/PiP, browser matrix, recovery and throttled playback tests.
6. **Settings.** Appearance, profiles, layout and language, playback/subtitles, provider management and diagnostics end to end.
7. **Polish and tests.** Add requested tests, run tsc/lint/build, check keyboard/accessibility and Lighthouse, record player results, write `web/README.md` and verify Source link. Push the approved `feat/website` branch after final review.

Each phase gets its own commit and approval before the next phase begins.
